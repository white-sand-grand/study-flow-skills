# HTML 学习库与增量更新

## 库的位置和续写

先找已有 `index.html`、章节/题库页面、CSS 与索引。原有 `physics-summary` 等目录就是有效库，无需改名或迁移。不同学科分库；当前目录含多个课程且无法判断归属时，询问归属以避免混库。

全新课程可使用如下小结构；按实际内容创建文件，不要预建空目录和空栏目：

```text
study-library/<course>/
  index.html
  assets/study-flow/v1/  # 固定 UI、本地公式运行时及字体
  chapter-<id>.html
  homework-<chapter>-<set>.html
  learning-index.json
  sources/<archived-inputs>
```

新增章节或作业后，同时更新总目录和知识点/题型入口。题目以稳定的来源及章题标识作为锚点；同一题的新解法优先补入原页。同一题号但不同版本/来源不能自动合并。修改已有页需保留有效链接；移动确有必要时同步修复引用。

默认按 `html-design.md` 的固定模板构建本次新增/更新页面，样式资源隔离到 `assets/study-flow/v1/`，避免覆盖旧库的 CSS。保留已有目录位置、页面 URL 和题目锚点；本次仅更新总目录入口时可保留旧总目录外观，不借机重做全部历史页。用户明确要求自定义或无需 HTML 时从其要求。把复习资产和来源留在课程目录；全局 skill 只保存工作流和通用模板，不包含个人教材内容、微信路径或课程解答。

“题型复习”采用 `question-type-review.md` 的 `kind: review` 设计，仍归属当前课程库；总目录添加复习入口，索引登记题型与题目来源，重建离线搜索，并执行相同增量规则。

## 再次运行：只处理增量

已有学习库时，不把再次运行理解成“从头重做整门课”。默认读取旧总目录、`learning-index.json` 和 `source-index.json`（或等价状态），识别新增/更新的 PDF、PPT、笔记和本次新作业。用户明确指定重新整理、换设计或重算旧题时才扩大范围。

使用标准库脚本辅助识别，内容指纹采用 SHA-256，不仅凭文件名或修改时间：

```text
python <技能目录>/scripts/scan_updates.py scan --course <课程目录> --library <课程库目录>
```

本次明确提供文件时以重复的 `--source <文件>` 限定范围；它支持课程目录外的作业附件。一般扫描会排除学习库、归档原图、UI 资源及隐藏/工具目录，避免把产物识别成新作业。

- `new`：未记录的文件；识别其课程、章节/题号后增补。
- `changed`：同路径文件内容变化；对照原材料，只更新受影响的章节/题目及关联汇总，保留其他旧内容。
- `unchanged`：已完成范围且内容不变，跳过，不生成重复页。只改时间戳而内容没变也应跳过。
- `pending`：之前只完成部分或等补充材料，继续未完成范围。
- `needs-rebuild`：已记录的输出页丢失；先恢复对应页，不把整门课重新整理。
- `new-selection`：同一文件新增明确选题范围，如旧题图中新指定另外两题；按新作业处理。传 `--scope <章节/题号/页码范围>` 来区分这种情况。普通再次运行不必指定 scope；显式新任务不能因文件没变而被误跳过。

旧库没有指纹记录时，先从既有页面/来源记录核对已处理范围并建立基线；不能把所有旧课件当作新课件重做，也不能未经核对把所有文件登记为已完成。新文件只是候选材料，不把目录中的所有照片都当指定作业。

读源材料前保存扫描给出的 hash；只有完成、落盘并验证后才登记该文件与实际范围。示例：

```text
python <技能目录>/scripts/scan_updates.py record --course <课程目录> --library <课程库目录> --source <已处理文件> --scope <course-summary或明确章题范围> --sha256 <处理前的指纹> --page <实际页面.html> --status complete
```

多页输出可重复传 `--page`；未完成用 `partial`，缺来源用 `needs-source`。脚本会拒绝把已在处理期间变化的源文件标成完成，也会检查输出页确实存在。`complete` 仅表示此次指定范围完成；没有覆盖文件其他部分时，不写成全文件已处理。保持 `learning-index.json` 中的内容范围及待办清单一致，后续优先续做其中明确未完成项。

若扫描没有增量、也没有本次新题目指示，只返回现有学习库入口及“无新增材料”，不重建旧页面。重复附件的文件名/路径变化时先按内容和题号去重；不要盲目把复制件当新题。源文件被删除或移动不代表应删除既有复习资产。

## 来源与内容索引

来自微信缓存、下载临时目录的题图应按此次用户提供范围复制存档；禁止移动或删除原件。文件名可采用有意义的章题名，冲突时增加后缀，不覆盖不同原图。记录原文件名及内容映射；附图与题干都要能定位。

已有稳定课程 PDF/PPT 可用相对路径引用并记录页码，避免不必要的全套复制。课件页码与 PDF 页码不同则分开标注。多份题图可以作为同题来源；题目被裁切时即使给了条件解，也在页面和索引标为待补充。

用轻量索引保存未来更新所需的信息。下面是结构示例而不是需原样复制的资产：

```json
{
  "course": "示例课程",
  "updated": "2026-10-23",
  "entries": [
    {
      "id": "book-a-ch02-p08",
      "kind": "problem",
      "language": "zh",
      "title": "第二章第8题",
      "page": "homework-ch02-set1.html#book-a-ch02-p08",
      "topics": ["知识点名称"],
      "problem_types": ["题型名称"],
      "sources": [
        {"file": "sources/ch02-p08.jpg", "original_name": "input.jpg", "locator": "第8题(a)-(c)"}
      ],
      "status": "complete",
      "exam_evidence": "homework",
      "notes": ""
    }
  ]
}
```

`kind` 可为 `chapter`、`problem`、`review`；`language` 为 `zh`/`en`（混合章节可为 `mixed`，具体题目单独分流）；`status` 为 `complete`/`partial`/`needs-source`；`exam_evidence` 可为空或用 `explicit`/`past-exam`/`homework`/`inferred`，具体依据写在 `notes` 或正文。只记录本次实际读取和处理的材料；不要把历史库未检查的页面自动标为已验证。

没有结构化索引的旧库可新增这个小文件，仅登记本次条目；不为补齐索引重做历史页面。已有等价索引则直接复用。日期使用用户时区和当日日期，不照搬示例。

## 阅读体验

- 使用 UTF-8、`lang="zh-CN"`、viewport、语义标题及目录/返回入口。英文题干和过程可标 `lang="en"`。
- 核心内容无需网络即可阅读。使用技能内打包的本地 KaTeX、字体及固定 UI，按 `formula-rendering.md` 逐式忠实渲染；无法支持的结构用可靠工具或原图，不能用简单 HTML 上下标/代码框降级代替完整公式，也不依赖 CDN。
- 题目分节与答案醒目，长英文/公式/表格在自己的容器内滚动。正文正常换行；不能用隐藏横向溢出来遮住内容，也不要全局 `word-break: break-all` 拆坏英文阅读。
- 图示影响理解时保留原图或用 SVG/HTML 绘制清晰的辅助图，注明重绘，不伪装成原书图。展示题干时提供文字与原图的对应位置。
- 配置打印样式，避免固定导航覆盖内容；复习自测可用 `<details>` 折叠答案，但打印时要能看到答案。
- 可按知识点和题型提供锚点/静态目录；材料多时按需增加纯本地搜索。不为几道题搭建数据库或 Web 服务。

## 验收

1. 逐项核对用户要求的章节、题号、子问与实际产物；全部涉及题型应能回到材料定位。中文分支无例行翻译、双语词表、英文过程，英文分支顺序与内容齐全。
2. 用技能内 `scripts/check_library.py` 检查实际学习库。传课程库的目录路径，脚本不会改写文件；输出 `FAIL` 的缺失路径/锚点应修正。它允许相对链接指向现有库外课程材料，也不会联网检查网站。
3. 读取 `learning-index.json` 时用标准 JSON 工具检查可解析、条目引用对应真实内容；脚本不替代此内容核对。
4. 有可用浏览器时从本地打开总目录和本次页面，检查桌面、窄屏及打印；长公式/表格不撑开整页，图像路径和折叠自测可用。无浏览器时报告未做视觉验证。
5. 最后交付本次页与总目录，说明待补题干/未验证答案/工具限制。只清理本次产生且不再需要的中间文件，不删除来源资产或用户旧资料。
